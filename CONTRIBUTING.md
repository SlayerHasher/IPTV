# Contributing

Спасибо за интерес к проекту! Ниже — простые правила, которые помогут вашему вкладу быть принятым.

## Что можно улучшать

- 🐛 **Баги** в `parser.py` (парсинг M3U, категоризация, статистика жизни) и `dashboard.html`
- 🌱 **Новые источники** — надёжные `.m3u`-плейлисты с русскоязычными каналами
- 🗂 **Категоризацию** — ключевые слова в `get_category_fallback()` и маппинг EPG-категорий
- 🎨 **Оформление дашборда** и README

## Как внести изменения

1. Сделайте Fork репозитория и создайте ветку: `git checkout -b feature/my-improvement`
2. Внесите изменения. Если правили `parser.py` — прогоните локально:
   ```bash
   pip install requests
   python parser.py
   ```
   Убедитесь, что `playlist.m3u`, `stable_streams.json` и `stable.m3u` генерируются без ошибок.
3. Если правили `dashboard.html` — откройте его локально (`python -m http.server`) и проверьте все вкладки без ошибок в консоли браузера.
4. Оформите коммит в стиле Conventional Commits: `feat: ...`, `fix: ...`, `docs: ...`, `chore: ...`
5. Откройте Pull Request с описанием **зачем** нужны изменения.

## Чего делать не стоит

- ❌ Не добавляйте платные/взломанные источники и приватные токены доступа
- ❌ Не удаляйте файлы статистики (`stable_streams.json`) — они накапливаются ежедневно и обнуление потеряет историю периодов жизни
- ❌ Не переформатируйте весь файл целиком без функциональной причины — это затрудняет ревью

## Стиль кода

- `parser.py` — Python 3.11+, стандартный стиль PEP 8, комментарии на русском допустимы
- `dashboard.html` — self-contained (без внешних зависимостей), интерфейсные строки на русском
- CI workflow запускается автоматически на каждый push — убедитесь, что он зелёный

## Сообщения об ошибках

Открывайте Issue с: описанием проблемы, примером канала/URL из плейлиста, логом GitHub Actions (если проблема в автообновлении).
